### EVD-20260811-001 — 모바일 upload disposition과 v4 state integrity

- 생성: 2026-08-11 KST / 작성자: Codex
- 환경·데이터: `local` / `synthetic`·`test fixture` only
- 출처: source commit [`a9a57cc`](https://github.com/Jaemani/Surisuri-Masuri/commit/a9a57ccb424ad6b6b66983e201436990d426e970), WSL2 local verification
- 저장 위치: 저장소의 source/test와 이 인덱스. 원본 GPS·사용자 식별정보·인증정보 없음
- 상태: `generated` — 사람 검토 대기

#### 확인한 범위

- Upload lease의 bounded FIFO/integrity scan과 첫 100개가 미래 상태일 때의 global due
  fallback 후보 재검증.
- Exact stored body digest, canonical retry/lease/attempt metadata, binding count와
  `position=0..sample_count-1` 연속성의 fail-closed 경계.
- ACK·hold·retry disposition이 parent upload batch와 bound outbox child를 하나의
  exclusive transaction에서 전이하는지 확인.
- Schema v4 migration이 writer lock 뒤 `user_version`을 읽고 invalid terminal state,
  body/binding 및 position gap/out-of-range/fractional을 모든 batch 상태에서 거부하는지
  확인.
- BEGIN/ROLLBACK lifecycle, COMMIT 응답 유실 뒤 fresh query-only correlation의
  `committed`/`not_committed`/`unverifiable` 결과를 확인.

#### 실행·관측 기록

- Mobile test: 15개 test file, 229 tests 통과.
- TypeScript check: 통과.
- Android·iOS Expo static export: 양쪽 통과.
- Workspace check/test: 통과.
- Firebase Rules: 24 tests 통과.
- 관련 source/test 변경: `apps/mobile/src/telemetry/`의 database, migration,
  upload lease/disposition/coordinator/retry 파일과 회귀 테스트.

#### 재현 명령

저장소 루트에서 다음 gate를 실행한다.

```bash
rtk pnpm --filter @mobility-reliability/mobile test
rtk pnpm --filter @mobility-reliability/mobile check
rtk pnpm --filter @mobility-reliability/mobile build
rtk pnpm check
rtk pnpm test
```

#### 증명하는 것

이 source와 synthetic/test fixture 범위에서 mobile local upload state의 atomic
disposition, migration integrity, bounded due fallback과 commit uncertainty에 대한
fail-closed 결과를 재현한다.

#### 증명하지 못하는 것

- 실제 Expo `useNewConnection` 두 connection의 SQLite contention과 busy-timeout loser
- HTTP upload/reconnect, server idempotency와 acknowledgment
- Firebase Auth/App Check 및 server-managed scope
- Android/iPhone 실기기 E2E, staging/production 배포, 실제 사용자·복지관 성과

#### 사용처와 역링크

- 결정: [ADR-0036](../decisions/ADR-0036-fail-closed-mobile-upload-lease.md), [ADR-0039](../decisions/ADR-0039-atomic-mobile-upload-disposition.md)
- 제품 업데이트: [UPD-20260811-01](../product-updates/UPD-20260811-01-mobile-upload-disposition.md)

### EVD-20260811-002 — R07 합성 품질 데이터셋 계약과 결정론적 split

- 생성: 2026-08-11 KST / 작성자: Codex
- 로드맵 위치: 8월 R07 중 A단계(모델 학습 전 데이터 계약)
- 환경·데이터: WSL2 / Python 3.12.3 / uv 0.8.13 / synthetic only
- 출처: source commit [`a20a85b`](https://github.com/Jaemani/Surisuri-Masuri/commit/a20a85b), WSL2 local verification, [CI run 31418403649](https://github.com/Jaemani/Surisuri-Masuri/actions/runs/31418403649)
- 저장 위치: 계약·generator·test는 저장소, 생성 dataset/manifest는 `/tmp` 검증 후 비커밋
- 상태: `generated` — 사람 검토 대기

#### 확인한 범위

- `quality-label.v1`의 네 known class와 `review_required`·`abstained` 상태를 분리했다.
  `unknown_review_required`는 학습 class로 허용하지 않는다.
- `quality-dataset-manifest.v1`에 telemetry/label/feature/generator/split version, seed,
  source, trace·label·split count, dataset/trace SHA-256과 benchmark eligibility를 고정했다.
- seed `20260811`로 `(0, 0)` 주변의 가상 trace 48개, sample 576개를 생성했다. 네 class는
  각각 12개이며 train/validation/test는 각각 16개다.
- 각 batch를 기존 `telemetry-batch.v2` JSON Schema로 검증하고, dataset과 label,
  manifest의 ID·count·hash·provenance linkage를 다시 대조했다.
- 모든 sample의 aware timestamp를 UTC로 정규화해 group/time holdout을 검사한다. 같은
  `scenarioGroupId`의 split 중복, sample 시간 역행·split 침범, trace/첫 sample 불일치,
  마지막 sample 이전 `sentAt`을 거부한다.
- `developer_device`와 benchmark 비대상 trace, 중복 trace/batch ID, 비객체 dataset/trace,
  schema validator 부재를 fail-closed 처리했다. 검증 오류는 경로·keyword만 반환하고
  좌표·payload 값을 포함하지 않는다.

### EVD-20260811-003 — R07 feature contract와 synthetic rules baseline

- 생성: 2026-08-11 KST / 작성자: Codex
- 로드맵 위치: 8월 R07-B feature·baseline gate
- 환경·데이터: WSL2 / Python 3.12 `.venv` / Node Ajv / synthetic only
- 출처: source commit [`a9b20d9`](https://github.com/Jaemani/Surisuri-Masuri/commit/a9b20d9), local commands
- 저장 위치: contracts·ML source/test·문서. generated dataset은 repository 밖 임시 경로
- 상태: `generated` — 사람 검토 대기

#### 확인한 범위

- `quality-features.v1`이 named numeric features와 nested trace/batch/dataset/feature
  lineage/hash만 기록하고 raw coordinates, raw samples, PII, label, prediction을
  반환하지 않는지 확인했다.
- malformed sample, missing accuracy, coordinate/sequence/time 오류와 non-synthetic
  source를 `review_required`/value-free reason code로 닫는지 확인했다.

  받지 않고, `quality-baseline-result.v1`의 source/provenance/metric/prediction
  contract를 만족하는지 확인했다.
