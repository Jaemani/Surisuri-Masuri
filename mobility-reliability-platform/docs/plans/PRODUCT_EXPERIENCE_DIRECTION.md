# 모바일·운영 콘솔 제품 경험 방향

- 작성일: 2026-08-13
- 상태: 시각 방향 선택 전 제품 구조 확정안
- 대상 기간: 2026년 5월~12월 로드맵
- 현 화면 근거: [모바일 앱 현재 UX 감사](../reports/human/HR-20260813-04-mobile-ui-audit.md)
- 웹 검증 경계: [ADR-0042](../decisions/ADR-0042-web-ui-preview-boundary.md)

## 한 제품, 두 개의 전혀 다른 과업

모바일과 복지관 운영 콘솔은 같은 데이터 체계를 사용하지만 같은 화면을 축소·확대해서는 안 된다.

| 제품 표면 | 주 사용자 | 한 문장 목표 | 기본 첫 화면 |
| --- | --- | --- | --- |
| 모바일 | 전동보장구 이용자·보호자 | 오늘의 이동을 쉽게 기록하고 안전하게 저장됐음을 확인한다 | 오늘 상태와 큰 `주행 시작` |
| 운영 콘솔 | 복지관 담당자 | 오늘 조치해야 할 점검·수리·동의·데이터 예외를 찾고 처리한다 | 오늘의 운영 큐 |

공통 브랜드는 차분하고 신뢰 가능해야 하지만 정보 밀도는 다르게 가져간다. 모바일은 한 화면 한 행동, 콘솔은 예외 우선 업무 밀도를 원칙으로 한다.

## 모바일 정보구조

### 1. 오늘

- 제품명과 인사 또는 오늘 날짜
- 현재 기기 상태: `이동 준비가 되었어요`, `점검이 필요해요`, `데이터가 부족해요`
- 하나의 큰 `주행 시작` 버튼
- 최근 주행 요약 한 줄
- 설정·도움말은 보조 위치

### 2. 주행 기록 중

- 가장 큰 상태: `이동을 기록하고 있어요`
- 경과 시간과 추정 이동거리
- `휴대폰에 안전하게 저장 중` 같은 사용자 결과 중심 상태
- 화면 하단 고정 `주행 종료`
- 종료 확인은 실수 방지를 위해 한 번 제공

### 3. 주행 완료

- `오늘 주행이 저장되었습니다`
- 시작·종료 시각, 이동거리, 기록 품질
- 점검 신호가 있을 때만 다음 행동 안내
- 홈으로 돌아가기

### 4. 복구·권한

- `중단된 기록 발견` 대신 `기록이 잠시 멈췄어요`
- `계속 기록`과 `이동 마치기`
- 위치 권한은 필요한 순간 짧게 설명
- background permission은 설정 화면에서 명시적 opt-in

### 사용자 화면에서 제외

- GPS sample 수와 rejected count
- upload batch·queue·delivery scope
- foreground/background/dev build 표기
- SQLite·schema·검증 상태
- 원본 좌표

이 정보는 개발자 진단 화면과 운영 증거로 분리한다.

## 복지관 운영 콘솔 정보구조

### 1. 오늘의 운영

- 점검 임박, 미처리 수리, 위험 신호, 기기 미배정, 동의 문제, 데이터 최신성 예외
- 숫자를 누르면 바로 처리 큐로 이동
- 마지막 갱신 시각과 데이터 부족 경계

### 2. 기기·점검 큐

- 가명 기기 코드, 상태, 최근·다음 점검일, 위험 상태, 데이터 품질, 마지막 동기화
- 위험·점검 지연·미배정·동의 문제·데이터 부족 필터
- 상세: 상태 → 수리·부품·점검 timeline → 근거 → 다음 조치

### 3. 수리·부품

- QR로 연결된 수리·교체·점검 event
- 담당 수리사와 처리 상태
- 전문가 판단은 모델 결과와 분리해 provenance 보존

### 4. 사용자·기기·동의

- 기본은 가명 또는 내부 표시 코드
- active assignment, 목적별 동의, 철회·삭제 처리 상태
- 일반 운영 화면에서 이름·연락처·상세 주소 숨김

### 5. 데이터·시스템 운영

- 동기화 지연, accepted/replay/rejected 비율, projector lag, DLQ
- model input missingness·abstention, report validation 실패
- 민감값 없이 correlation ID로 추적

### 6. 보고서·내보내기

- 기간·모수·데이터 품질·제한·Fact ID·계산 기준일·버전
- 근거 없는 문장은 제외 또는 `확인 필요`
- canonical model과 기관별 Excel/PDF adapter 분리

### 7. 권한·감사

- tenant·role 권한
- 동의 철회·삭제 진행
- export·access audit

## 콘솔에서 기본 제외

- GPS 원본 sample와 개인별 이동경로 재생
- 정확한 출발·도착·자택·복지관 좌표
- raw storage batch와 내부 object path
- 이름·전화번호·상세 주소·Firebase UID·token
- 소수 인원으로 재식별 가능한 지역 셀

표시 가능한 값은 기간 누적 사용량, 품질·위험 상태, 마스킹 derived summary, 충분한 모수를 갖춘 익명 지역 집계다.

## 공통 디자인 원칙

1. 기술 상태를 사용자 결과 문장으로 번역한다.
2. 색상만으로 상태를 전달하지 않는다.
3. 모바일은 48dp 이상 조작 영역과 16px 이상 본문을 기본으로 한다.
4. 위험도는 단일 건강점수가 아니라 상태·근거·데이터 부족을 함께 표시한다.
5. 지도는 제품의 장식이 아니다. 사용자의 과업에 필요하고 개인정보 경계를 지킬 때만 사용한다.
6. 모든 실제 값, 합성 값, 계획 값은 화면과 보고서에서 구분한다.
7. 모바일과 콘솔은 공통 색·타입·상태 언어를 쓰되 동일한 카드 배치를 복제하지 않는다.

## 검증 전략

- 매 UI 변경: Expo Web + Playwright 390×844 및 콘솔 desktop viewport
- 매 native milestone: Android emulator와 실제 Android/iPhone 검증표
- 접근성 gate: 큰 글씨, TalkBack·VoiceOver, 대비, focus, 한 손 조작
- 현장 gate: 이용자/보호자 `시작→기록 확인→종료 확인`, 담당자 `예외 발견→근거 확인→조치 기록`
