# 모바일·복지관 콘솔 제품 경험 기준

- 갱신일: 2026-08-13
- 상태: approved baseline
- 기준 결정: [ADR-0043](../decisions/ADR-0043-welfare-center-repair-operations-product-core.md)
- 시각 검증 경계: [ADR-0042](../decisions/ADR-0042-web-ui-preview-boundary.md)

## 제품의 중심

제품의 시작과 끝은 GPS가 아니라 다음 업무 흐름이다.

```text
사용자 증상 접수
→ 복지관 검토·수리소 배정
→ 수리사 QR 확인·진단·작업 제출
→ 복지관 비용·지원금 검증
→ 사용자 완료 내용 확인
→ 기기·부품 타임라인과 다음 점검 갱신
```

GPS와 AI는 사용량과 수리 이력에 근거한 예방점검을 개선한다. 위치 동의가 없어도 수리·기기·지원금 기능은 사용할 수 있어야 한다.

## 하나의 모바일 코드베이스, 역할별 제품

### 사용자·보호자

#### 홈

1. 진행 중 수리와 다음 약속
2. 남은 지원금과 현재 기기 상태
3. 지금 필요한 행동 하나
4. 선택적인 이동 사용량 기록 상태

#### 수리

- 증상 중심 요청: 소음, 배터리 소모, 브레이크, 타이어, 조작부, 시트·프레임, 기타
- 사진·음성·간단 메모
- 기관 정책에 따른 수리소 직접 선택 또는 복지관 배정
- 접수→검토→배정→예약→수리→기관검증→완료 상태
- 견적, 실제 청구액, 지원금, 본인부담
- 완료 확인과 이의 제기·재개방
- 완료 수리기록은 사용자가 작성하거나 덮어쓰지 않음

#### 내 기기

- 모델, 제조·구매일, QR 공개코드
- 현재 배정과 기기 상태
- 수리·점검·부품 교체 타임라인
- 사용량 요약과 다음 점검 권고
- 권고 근거, 데이터 충분도, 판단 유보

#### 복지지원

- 정책 기간과 연간 한도
- 예약액, 집행액, 취소액, 잔액
- 수리 건별 지원금과 본인부담
- 적용 가능한 지원, 기관 공지·서류·담당자 연결

#### 설정·알림

- 수리·점검·지원금·보호자 알림
- 위치수집 목적별 동의와 현재 상태
- 위치 권한과 백그라운드 수집은 이 영역에서 명시적으로 관리

기존 16문항 자가점검은 사용자 필수 과업이 아니다. 사용자는 짧은 증상을 접수하고 정식 점검표는 수리사·복지관이 작성한다.

### 수리사

- 배정 작업과 일정
- QR 스캔 또는 공개코드 입력
- 사용자 증상, 기기·부품·수리 이력
- 구조화 진단, 점검표, 부품, 배터리 전압, 작업 전후 증거
- 견적과 실제 청구액
- 작업 완료 제출
- 예방정비 권고 동의·정정·판단 보류

수리사는 작업을 제출하지만 공적 지원 건의 최종 검증은 복지관 책임이다.

## 복지관 운영 콘솔

### 오늘 할 일

- 신규·미검토·미배정·지연 수리
- 수리사 제출 후 기관 검증 대기
- 점검 예정·연체
- 지원금 초과·중복·증빙 누락
- 담당자·기기 미배정
- 동의·데이터 부족으로 사람 검토가 필요한 건

### 이용자·보호자

- 등록, 수급 유형, 관할, 담당자
- 보호자 관계와 연락·알림·위치 동의
- 배정 기기, 수리·점검·지원금 이력
- PII 조회 감사

### 기기 관리

- 등록, 배정, 이관, 회수, 폐기
- QR 발급·재발급
- 모델·제조·구매일과 현재 상태
- 수리·점검·부품 타임라인
- 사용량 요약과 예방점검 권고

### 수리 운영

- 요청 접수·대리 등록
- 증상 분류와 우선순위
- 수리소·수리사 배정
- 예약과 상태 관리
- 견적·실비·증빙
- 완료 검증, 반려·정정·재개방
- 다음 점검 예약

### 예방점검

- 예정·연체 대기열과 일괄 연락
- 고정주기와 모델 권고 구분
- 근거, 신뢰구간, 데이터 부족·abstention
- 수리사 전문 피드백

### 지원금 원장

- 정책 버전과 적용기간
- allocation, reservation, execution, release, reversal, adjustment
- 기관 부담과 본인부담
- 수리 건 연결과 초과·중복·증빙 예외
- 모든 수동 조정의 담당자·사유·시각

### 파트너·보고서·시스템

- 수리소 연락처, 담당 지역, 가능 수리, 배정량·응답 상태
- 기간·기기·부품·수급유형별 건수와 비용, 반복수리, 점검 이행률
- 기관별 Excel/PDF adapter와 Fact ID
- 직원 역할, PII·위치 접근 감사, 이관 검역, sync·모델·리포트 오류

원본 GPS sample, 개인별 정밀 경로, Storage object path는 기본 업무 화면에 표시하지 않는다.

## 디자인 및 검증 원칙

1. 모바일은 수리·지원의 다음 행동을 먼저, GPS는 보조 영역에 표시한다.
2. 모바일 조작 영역은 48dp 이상, 본문은 16px 이상을 기준으로 한다.
3. 콘솔은 예외 우선 밀도를 유지하되 주요 상태·금액·버튼을 정상 배율에서 읽을 수 있어야 한다.
4. 상태는 색상뿐 아니라 텍스트·아이콘·순서로 전달한다.
5. 모델 값은 근거·데이터 충분도·판단 유보와 함께 표시한다.
6. demo·synthetic·field·production 데이터를 화면과 보고서에서 구분한다.
7. Expo Web/Playwright는 빠른 시각 검증이고 native lifecycle 증거를 대신하지 않는다.
8. 현장 검증 과업은 사용자 `증상 접수→진행 확인→비용 확인`, 수리사 `QR→작업 제출`, 담당자 `접수→배정→검증→원장`이다.
