# ADR-0057 — 예방점검 화면은 예측 점수보다 근거·유보·다음 조치를 먼저 보여준다

- 상태: accepted / local synthetic web 구현 검증
- 결정일: 2026-08-13
- 영향 범위: 복지관 콘솔 예방점검 화면, R10 설명 UX
- 선행 결정: [ADR-0056](./ADR-0056-r10-synthetic-reliability-baseline.md)

## 맥락

기존 예방점검 화면은 합성 이용자별 `주의·관찰·양호`와 `신뢰도 높음`을 표로 표시했다. 이 표현은 실제 reliability field metric과 개별 기기 판정이 없는 현재 상태를 숨기고, 합성 데모 값을 운영 판단처럼 보이게 할 수 있다.

## 결정

- 화면을 `운영 검토`, `판단 유보`, `등록 일정` 세 상태로 나누고 출처를 이용자 접수·데이터 품질·운영 일정·검증 이력으로 표시한다.
- 각 항목은 현재 확인된 근거, 아직 필요한 정보, 다음 운영 조치를 분리한다.
- 데이터가 부족한 항목에는 점수·신뢰도·고장 확률을 표시하지 않고 `판단 유보`로 닫는다.
- 이용자 진술은 센터 검증 사실과 구분하고, 일정은 모델 판정이 아니라 기관이 등록한 운영 일정으로 표시한다.
- 화면 전체에 합성 데모임을 유지하고 고장 시점·안전 보증이 아니라는 문구를 노출한다.
- 이 UI는 R10 aggregate baseline metric/curve를 개별 이용자나 기기에 연결하지 않는다.

## 검증과 한계

React console의 예방점검 화면을 local synthetic 데이터로 구현하고 Playwright에서 목록 선택→판단 유보→부족한 거리 요약→다음 조치 흐름을 확인했다. 1440×1024 스냅샷에서 요약 카드, 검토함, 근거 상세의 위계를 시각 검토했다.

실제 복지관 이해도, 키보드 전체 순서, screen reader, production Firebase projection, 실제 점검 수행·사용자 성과는 검증하지 않았다.
