## 목적

수리 이력과 누적 주행량을 이용해 부품별 time-to-inspection을 추정할 수 있는지 검증한다. 모델 성능이 충분하지 않으면 규칙 기반 점검 주기를 유지하도록, 실패 가능한 실험으로 정의한다.

## 계획상 논의

- 수리, 실제 고장, 예방 교체, 단순 상담을 outcome에서 구분하는 방법
- 관측 시작·종료, censoring, 부품 교체 후 risk clock 재설정
- 고정 기간, 누적 주행거리 임계값, Cox/Weibull, survival forest 후보
- 동일 기기 이력이 train/test에 섞이지 않는 시간·그룹 분할
- 부품별 표본 부족, 기관·기종 편향, 누락 주행량의 영향
- 승인된 Cloud Storage manifest와 Firestore 수리 export를 결합하고, optional BigQuery 사용 시 partitioned snapshot과 query 비용을 고정하는 데이터 계보
- 사용자에게 고장 예측이 아닌 점검 권장 위험으로 표현하는 원칙

## 결정 예정 항목

- 학습 가능한 outcome과 제외할 수리 유형
- baseline 및 후보 모델의 비교 기준
- 30일 위험도, 권장 점검 구간 등 출력 형식
- 데이터 부족·distribution shift 시 abstention 조건
- 모델 실험·Storage manifest/Firestore export 또는 optional BigQuery snapshot 계보를 보존하는 버전 체계

## 기대 산출물

- 신뢰성 데이터셋 및 모델 카드 초안
- Kaplan–Meier 또는 동등한 부품별 위험 곡선
- 고정 점검주기·거리 규칙·생존모델 비교표
- time-split 평가와 대표 실패 사례
- 부품 건강 화면의 저충실도 설명 UX

## 검증 지표

- outcome과 censoring 생성 규칙이 재현 가능한가
- baseline 대비 discrimination뿐 아니라 calibration도 측정했는가
- 부품별 표본 수와 신뢰구간을 성능표에 함께 표시했는가
- 근거가 부족한 케이스에서 모델이 안전하게 유보하는가

## 실제 진행 입력란

### 2026-08-13 reliability baseline result contract 선행 snapshot

`reliability-baseline-result.v1` strict schema와 synthetic valid/invalid fixture를 추가했다. 결과 범위는 `synthetic_only`와 `trainingPerformed=false`로 고정하고, `device-group-time-holdout.v1` 시간 분할·leakage flag·counts reconciliation·fixed interval/누적거리/Kaplan–Meier 비교 구조·component별 `data_insufficient` abstention·`deploymentAuthorized=false`/`defer`를 계약으로 제한했다. contracts validator 전체 36개 fixture case와 reliability baseline valid/invalid 2개가 통과했다. 이는 local contract fixture 검증이며 실제 event/censoring 데이터, 위험곡선, calibration, field 성능 또는 배포를 증명하지 않는다. 근거: [ADR-0055](../../decisions/ADR-0055-reliability-baseline-result-contract.md), [UPD-20260813-25](../../product-updates/UPD-20260813-25-reliability-baseline-result-contract.md), [EVD-20260813-021](../../evidence/2026-08-product.md#evd-20260813-021--reliability-baseline-time-splitcensoringabstention-contract).

선행 기술 increment로 합성 component episode generator와 device-group/time holdout, fixed interval·30일 누적거리 도달·Kaplan–Meier 기준선 evaluator를 구현했다. risk clock reset은 동일 기기·부품·시각의 명시적 synthetic replacement event만 허용하고, 거리 feature의 decision-time cutoff와 finite 값을 검사한다. train evidence가 부족하면 metric 없이 abstain하며 runtime은 schema 밖의 count·시간창·동일 cohort invariant와 결과 hash를 검증한다. 신규 14개를 포함한 ML 87 tests가 local CPU에서 통과했다. 이는 synthetic pipeline 재현 결과이며 실제 부품 위험도나 field 성능이 아니다. 근거: [ADR-0056](../../decisions/ADR-0056-r10-synthetic-reliability-baseline.md), [UPD-20260813-26](../../product-updates/UPD-20260813-26-r10-synthetic-reliability-baseline.md), [EVD-20260813-022](../../evidence/2026-08-product.md#evd-20260813-022--r10-local-synthetic-reliability-baseline).

복지관 콘솔 예방점검 화면의 합성 위험 표를 근거 중심 검토 workspace로 교체했다. 이용자 접수·데이터 품질·운영 일정·검증 이력을 분리하고, 확인 사실·부족 정보·다음 조치를 보여준다. 데이터 부족은 숫자 없이 판단 유보한다. Playwright console 4 flows와 1440×1024 시각 snapshot을 검증했다. 이는 synthetic web 설명 UI이며 실제 개별 기기 판정이나 기관 성과가 아니다. 근거: [ADR-0057](../../decisions/ADR-0057-console-inspection-evidence-ui.md), [EVD-20260813-023](../../evidence/2026-08-product.md#evd-20260813-023--console-예방점검-근거유보-ui).

합성 기준선 비교를 identity-free presentation artifact와 콘솔 보고서로 연결했다. train 규칙·KM curve와 untouched test metric을 분리하고, 배터리 aggregate metric과 controller 표본 부족 유보를 표시한다. 화면 수치는 evaluator가 만든 hash-bound artifact snapshot을 직접 읽으며 synthetic-only·read-only·deployment defer를 노출한다. contracts 38 cases, ML suite, console 16 tests/build와 Playwright 5 flows를 local에서 검증했다. 이는 실제 field metric이나 개별 기기 판단이 아니다. 근거: [ADR-0058](../../decisions/ADR-0058-r10-synthetic-reliability-presentation.md), [EVD-20260813-024](../../evidence/2026-08-product.md#evd-20260813-024--r10-합성-reliability-비교-presentation).
