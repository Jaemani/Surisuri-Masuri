## 목적

사용자·수리사·복지관 리포트를 생성하되 모든 핵심 주장에 검증 가능한 Fact ID를 연결하는 AI report agent를 설계한다. 근거가 없거나 스키마를 위반한 문장은 차단·수정·유보하도록 실행 루프를 구성한다.

## 계획상 논의

- 통계·모델 출력을 정규화하는 Fact Store와 fact provenance
- 대상별 report JSON Schema 및 허용되는 주장 유형
- planner→writer→validator→fallback으로 구성한 실행 상태
- claim–evidence entailment, 수치 일치, 날짜 범위, 금지 표현 검사
- 모델/API 실패, timeout, invalid JSON, 근거 부족의 실패 분류
- 프롬프트·모델·도구 호출·검증 결과를 재현 가능하게 기록하는 receipt

## 결정 예정 항목

- Fact ID 형식과 불변성·버전 규칙
- 대상별 필수·선택 보고서 섹션
- 규칙 기반 validator와 모델 기반 validator의 경계
- 근거 없는 주장 발견 시 삭제·재생성·확인 필요 처리
- 에이전트 평가셋과 배포 승인 지표

## 기대 산출물

- Fact Store 스키마와 샘플 fact bundle
- report agent 실행 상태도와 provenance receipt
- 사용자·수리사·복지관 리포트 예시
- 공격·결측·모순 입력 평가셋
- claim–evidence 검사 결과 및 fallback 데모

## 검증 지표

- 모든 주요 수치·권장 문장에 유효한 Fact ID가 존재하는가
- 근거 없는 문장·수치 변조·오래된 데이터가 평가셋에서 탐지되는가
- 같은 입력과 버전 정보로 실행 경로를 재현할 수 있는가
- LLM 장애 시 핵심 사실을 규칙 기반 보고서로 제공할 수 있는가

## 실제 진행 입력란

- 실제 수행 내용: 2026-08-13 local 선행 increment에서 R11 합성 assessment를 5개 typed Fact와 5개 Fact ID 연결 claim으로 변환하는 deterministic fallback을 구현했다. 이 정기리포트의 실제 10월 발행·회의를 의미하지 않는다.
- 모델/프롬프트/평가셋 버전:
- groundedness·schema·fallback 결과: claim Fact coverage 5/5, LLM 호출 0, fallbackUsed true. report-evidence 7 tests와 console snapshot exact equality 통과.
- 실제 결정 및 보류:
- 발견한 심각 오류/완화:

### 2026-08-13 선행 기술 snapshot 후속 — 회의·발행 아님

최초 7-test fallback 뒤 source assessment self-hash, 정확히 5개인 Fact·claim profile, claim의 tenant·parent 결합, 생성→검토→발행 lifecycle, unsupported 후보 omission을 순차 추가했다. 현재 report-evidence는 17 tests, Firebase Rules는 41 tests다. 이 수치는 local synthetic/Emulator 코드 경계이며 실제 10월 회의, LLM 실행, Firebase writer, 사람 검토·발행 또는 기관 보고서가 아니다.

- 실제 결정: 근거 없는 후보를 문구 수정으로 살리지 않고 omit한다. generation 완료를 review/publication과 분리한다.
- 보류: LLM worker, persistence writer, production Auth/App Check, 사람 승인 receipt, 실제 기관 데이터.
- 오류 완화: source nested 변조, incomplete profile, foreign tenant/parent claim, orphan claim, post-terminal transition을 fail-closed한다.
