## 목적

학습한 데이터 품질 모델을 ONNX로 변환해 모바일에서 실행하고, 서버 추론 없이도 수집 품질 플래그를 생성할 수 있는지 검증한다. 기기별 성능 차이와 모델 fallback까지 포함해 배포 가능성을 판단한다.

이 목적은 R07에서 배포 후보가 선택됐을 때만 활성화된다. 현재는 field holdout 또는 rules 대비 의미 있는 오류 개선이 생길 때까지 계획 상태를 유지한다. 그 전에는 실기기 제품 smoke와 동의된 field 수집·라벨링 준비가 선행 작업이다.

### 2026-08-13 선행 코드 snapshot

ONNX를 실행하지 않고, 실제 동의 trace가 생길 때 학습과 분리해 평가할 `quality-field-holdout.v1` 입장 계약과 `quality-field-features.v1` 추출 계약을 먼저 구현했다. holdout과 telemetry의 trace·batch·canonical hash가 정확히 일치할 때만 공통 numeric core를 실행하며 출력에는 좌표·label·split·가명 group·동의 digest가 없다. 합성 fixture와 생성 batch는 평가 전용·학습 불가·배포 불가 경계를 검증할 뿐이다. 실제 field data나 동의 state는 사용하지 않았으며, 이 결과는 모델 효용·field 성능·ONNX 완료가 아니다. 근거: [EVD-20260813-013](../../evidence/2026-08-product.md#evd-20260813-013--field-holdoutfeature-admission-계약).

같은 날 합성 train split의 PyTorch 후보를 재학습 없이 평가할 frozen artifact도 구현했다. 가중치, train-only 정규화, feature/class 순서와 dataset·manifest·state·file hash를 고정하고 CPU `weights_only` strict load와 gradient-off prediction을 검증한다. 이는 local synthetic 평가 재현 기반이며 실제 field inference, ONNX, Android/iPhone 지연시간 또는 배포 완료가 아니다. 근거: [EVD-20260813-014](../../evidence/2026-08-product.md#evd-20260813-014--frozen-pytorch-load-only-artifact).

후속으로 field evaluation-only 결과 계약과 harness를 추가했다. label·feature가 모두 적격인 동일 trace set에 frozen rules와 모델을 실행하고 review/missing/count를 별도 보존하며, 결과는 학습 없음·배포 불가·결정 유보로 고정한다. 테스트는 생성 batch 한 건의 contract bridge이므로 실제 field metric이나 사용자 성능이 아니다. 근거: [EVD-20260813-035](../../evidence/2026-08-product.md#evd-20260813-035--field-evaluation-only-harness-계약).

## 계획상 논의

- PyTorch 체크포인트에서 ONNX export와 수치 일치 검증
- feature extraction을 Python과 모바일에서 동일하게 재현하는 계약
- float 모델과 quantized 모델의 크기·지연·정확도 비교
- Android/iPhone별 cold start, p50/p95 추론 지연, 메모리 사용량
- 입력 누락·비정상 길이·지원하지 않는 모델 버전의 fallback
- 모델 출력이 사용자 안전 판단이 아닌 데이터 품질 보조임을 UI에 반영

## 검증 지표

- 동일 입력에서 PyTorch와 ONNX 출력 차이가 정한 허용오차 이내인가
- 두 플랫폼에서 목표 지연시간과 메모리 한도를 만족하는가
- quantization 이후 class별 성능과 calibration 변화를 측정했는가
- 모델이 실행되지 않아도 GPS 원본 수집·동기화가 중단되지 않는가
