## 목적

Cloud Storage 주행 batch와 Firestore의 수리·점검·부품 교체 기록을 시간 순서대로 재생해 Firestore current projection을 재구성하는 과정을 설계한다. 과거 수리 데이터는 출처를 보존한 일회성 이관으로 편입한다. 같은 완료 수리 사실을 사용자 모바일과 복지관 콘솔이 읽도록 console read-time timeline 경계도 검토한다.

## 계획상 논의

- Storage batch/receipt에서 유도한 TripRecorded와 Firestore의 RepairLogged, PartReplaced, InspectionCompleted 등 도메인 이벤트
- immutable Storage 원본·Firestore 업무 기록과 서버만 쓸 수 있는 current projection의 역할 분리
- 늦게 도착하거나 정정된 이벤트가 projection에 미치는 영향
- projector 버전 변경 시 승인된 Storage manifest와 Firestore export/snapshot 기반 replay 및 checksum 검증
- 과거 DB 필드의 신규 이벤트 매핑, 미확인 값, 중복 수리 기록 처리
- GPS sample별 Firestore write 없이 trip summary와 현재 상태만 제한된 문서 수로 갱신하는 비용 경계
- Digital Twin 명칭은 시점별 상태 복원이 검증된 이후에만 사용하는 원칙
- 사용자 모바일과 복지관 콘솔이 동일한 verified completed-repair archive를 읽는지, role-purpose DTO가 분리되는지

## 결정 예정 항목

- 도메인 이벤트 목록과 필수 payload
- Firestore 기기·부품 current projection 스키마와 Security Rules
- 복지관 콘솔 `completedRepairTimeline` read-time DTO와 기기 상세 표시 범위
- 정정·취소 이벤트와 원본 불변성 규칙
- migration id, source record id, 변환 버전의 계보 구조
- replay 성능·정합성 검증 방식

## 기대 산출물

- 이벤트 카탈로그와 JSON Schema
- Storage manifest/Firestore snapshot 기반 상태 projector 및 특정 시점 replay PoC
- 기존 수리 데이터 migration dry-run 리포트
- 기기 타임라인과 부품별 상태 화면
- 원본 레코드→이벤트→현재 상태의 계보 조회
- Emulator Suite에서 client의 projection 직접 쓰기를 차단하는 Security Rules 테스트
- 콘솔 read-time replay의 순서 독립성·checksum·민감값 scan·빈 이력 처리 테스트

## 검증 지표

- 같은 이벤트 집합의 반복 replay 결과가 동일한가
- out-of-order 이벤트를 반영한 뒤 상태가 올바르게 교정되는가
- migration 전후 레코드 수와 제외·중복·미확인 수가 설명되는가
- 화면의 상태 값에서 근거 이벤트까지 추적할 수 있는가
- sample 수 증가가 Firestore projection write 수를 비례 증가시키지 않고, client의 projection 직접 쓰기가 차단되는가

### 2026-08-13 console 선행 코드 snapshot

콘솔 `devices` projection이 verified completed repair archive를 기기별로 bounded read하고, 모바일과 동일한 replay 검증 경계를 거쳐 목적 제한 timeline을 반환하도록 구현했다. console repository strict decoder와 기기 목록·상세 UI, 운영 CTA를 추가했고 local/Emulator/Playwright에서 검증했다. 근거는 [ADR-0051](../../decisions/ADR-0051-console-completed-repair-timeline-read-time-replay.md), [UPD-20260813-21](../../product-updates/UPD-20260813-21-console-completed-repair-timeline-plan.md), [EVD-20260813-017](../../evidence/2026-08-product.md#evd-20260813-017--console-완료-수리-타임라인)이다. 이는 production 배포나 기관 사용 완료가 아니다.

### 2026-08-13 device current-state pure replay snapshot

normalized repair, explicit component replacement, inspection과 raw GPS-free trip summary의 strict 계약과 pure replay를 구현했다. projector version·event checkpoint value·canonical checksum, out-of-order와 `asOf`, component 추정 금지를 local synthetic으로 확인했다. Firestore shadow state·atomic pointer·durable checkpoint worker는 후속 구현이며 아직 완료로 기록하지 않는다. 근거: [ADR-0052](../../decisions/ADR-0052-device-current-state-deterministic-replay.md), [EVD-20260813-018](../../evidence/2026-08-product.md#evd-20260813-018--device-current-state-deterministic-pure-replay).

### 2026-08-13 Firestore shadow projection promotion snapshot

pure replay 결과를 deterministic server-only shadow에 준비하고 authoritative device current와 per-device checkpoint를 하나의 Firestore transaction에서 승격하도록 구현했다. exact replay는 revision 1에서 수렴했고 input drift·tampered shadow는 current/checkpoint write 없이 거부됐다. Rules는 source/shadow/checkpoint를 전 client에게 숨기고 current를 운영자 read-only로 유지한다. 근거는 [ADR-0053](../../decisions/ADR-0053-firestore-shadow-projection-promotion.md), [UPD-20260813-23](../../product-updates/UPD-20260813-23-firestore-shadow-promotion-plan.md), [EVD-20260813-019](../../evidence/2026-08-product.md#evd-20260813-019--firestore-shadow-projection-atomic-promotion)이다.

### 2026-08-13 legacy repair dry-run bridge snapshot

기존 mapper acceptance와 verified source 승인을 분리하고 explicit device·repair UUID crosswalk와 recordedAt evidence를 모두 통과한 합성 record만 normalized `repair.recorded` 후보로 만드는 strict dry-run bridge를 구현했다. unknown date/device/category·conflict·unverified amount/source는 quarantine하고 component event를 추정하지 않는다. 결과 계약은 source record를 제외하고 dry-run/write/deployment false를 고정한다. 근거: [ADR-0054](../../decisions/ADR-0054-legacy-repair-device-state-event-dry-run.md), [UPD-20260813-24](../../product-updates/UPD-20260813-24-legacy-repair-dry-run-bridge-plan.md), [EVD-20260813-020](../../evidence/2026-08-product.md#evd-20260813-020--legacy-repairdevice-state-event-local-dry-run-bridge).
